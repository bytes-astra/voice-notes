# 审查缺陷修复设计

## 目标

修复已核实的 VoiceNotes 前后端契约、下载恢复、流式时间轴/内存与前端交互问题。保持现有架构、模型版本与识别参数不变。

## 范围

1. `LevelPayload`、`InputDevice` 使用 camelCase；界面 mock 与真实事件载荷一致。
2. 下载前删除超过目标大小的 `.part`；大小校验失败删除残留，后续可重新下载。
3. 流式 VAD 只用于门控，消费完检测结果立即 `clear()`。`StreamingSession` 单独跟踪真实输入采样数；录音编排对每块音频（包括预录与静音）只推进一次时间轴，送入识别器不再推进真实时间。缺口、句子与总时长使用同一时间轴。
4. 前端保留用户编辑；动态结果元信息可按 key 重绘；toast 所有定时器可取消；设备缺失时回退系统默认并同步设置；设备标签空时有回退；文件进度按当前数据重绘；过期文件任务无论在哪退出都复位；无 id 历史逐条删除；输入区 Esc 不导航；下载空来源不显示缓存；拼接在本地化之前执行。
5. 流式空文本/过短检查与整段一致，但时长以真实录音为准。

## 非目标

- 不改 VAD `max_speech_duration`、模型、热词、音频格式或识别流程。
- 不引入前端框架、构建器或新依赖。
- 不改变已有事件名、公开命令名或文本导出格式。

## 关键决策

- 时间轴归属 `StreamingSession`，提供按真实输入块推进的方法及当前秒数访问器；避免在 `record.rs` 另存第二份时间计数。
- `showTranscript` 只有文本仍等于上次渲染文本时才随语言重绘；用户编辑后仅更新缺口占位符，不覆盖其他字符。结果区字数始终跟随当前可见文本，音频时长和识别耗时仍来自转写结果。
- 动态元信息保留简短的结构化 key/参数，集中重绘，避免恢复已删除的静态 DOM。
- 文件 `finally` 的无条件复位保持现有 attempt 检查作为过期判断，但不能提前 return。
- 修复以纯逻辑 Rust 测试和真实前端模块的 WebKit 检查为主；真模型运行流式冒烟/长录音探针，不把打印型探针当作断言。

## 验收

每个缺陷先有失败回归测试，再最小实现。`npm run check` 和 `npm run check:ui` 全通过。用本机模型执行流式测试/长录音探针，记录结果。不提交构建产物或重新生成截图。
